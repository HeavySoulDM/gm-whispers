# GM Whispers — план и анализ (история)

> Живой план теперь в `ROADMAP.md`, техническое описание — в `ARCHITECTURE.md`. Этот файл — анализ задачи и ход работ до 9.10.2026; дальше он не правится.


*Версия 0.2 · 6 октября 2026 · тестовый мир: `Data/worlds/dod-test`*

## 0. Коротко

- **Делаем** помощника ГМа для Foundry VTT из трёх частей: советник по приключению, тактика за монстров и (со звёздочкой) слушатель Discord с подсказками по ходу игры. Плюс итоги сессии в журнал.
- **Схема:** модуль Foundry (панель только для ГМа) ↔ локальный сервер-компаньон на ПК ГМа (Python) ↔ Claude API. Discord-бот и распознавание речи живут в том же сервере.
- **Главный технический риск:** приём голоса из Discord. С 1 марта 2026 Discord требует сквозное шифрование DAVE, и у библиотек для ботов с *приёмом* звука под DAVE были серьёзные проблемы. Поэтому аудио проверяем отдельным коротким экспериментом (go/no-go) и только потом строим на нём.
- **Главный вывод по данным:** в мире около 2,5 млн символов русского текста. Целиком в каждый запрос это не отправишь, нужен поиск по базе знаний (RAG) со ссылками на источник.
- **Порядок:** сначала советник и тактика (польза сразу), потом аудио-эксперимент, итоги сессии и только в конце подсказки в реальном времени.
- **Ориентировочная стоимость:** $3–6 за четырёхчасовую сессию при локальном распознавании речи.

## 1. Что строим и по каким правилам

### Функции

| # | Функция | Как вызывается | Что получает ГМ |
|---|---|---|---|
| F1 | Советник по приключению | Вопрос в панели | Ответ со ссылками на журнал/страницу, учитывающий текущую сцену и партию |
| F2 | Тактика за монстров | Кнопка в трекере боя на ходу NPC | 2–3 варианта хода с логикой |
| F3 | Итоги сессии | После игры | Черновик журнала: события, NPC, обещания, висящие крючки |
| F4 | Подсказки в реальном времени | Кнопка «Что я упускаю?», триггеры, тихие сигналы | Карточки NPC/лора, напоминания, сигналы о темпе |

### Принципы (не обсуждаются)

1. **Решает ГМ.** Помощник только предлагает и сам ничего не двигает и не кидает.
2. **Видит только ГМ.** Никаких сообщений в чат, сокетов или настроек мира, которые доходят до игроков. Спойлеры не утекают.
3. **Ответ по лору всегда со ссылкой на источник** (журнал → страница). Если источника нет, так и пишем: «в книге не нашёл, это импровизация».
4. **Не шуметь.** Лучше 5 полезных подсказок за вечер, чем 50 проигнорированных.
5. **Боевой мир не трогаем.** Вся разработка идёт в `dod-test`. В `dod` переносим только готовое, отдельным шагом.

- По грубой оценке это 0,6–0,9 млн токенов. Технически влезает в окно 1M, но каждый запрос был бы медленным (десятки секунд) и дорогим. Поэтому **поиск по фрагментам + небольшая «библия кампании»** (сводка на 30–50 тыс. токенов), которая кэшируется.

## 3. Технологии по слоям

### 3.1 Модуль Foundry `gm-whispers`

- ES-модуль под v14, интерфейс на ApplicationV2 (как у `dod-config`), рендерится только при `game.user.isGM`.
- **Что делает:**
  - панель «Советник» (чат с помощником, лента подсказок, карточки);
  - кнопка «Что делать?» в трекере боя;
  - **сборщик контекста**: сцена, токены и расстояния, бой, HP/состояния/концентрация, привязанные журналы, активные эффекты, состояние `dod-time-loop`;
  - **экспорт базы знаний**: журналы мира и компендиумов (`mir-drakkenhajma`) отправляются на сервер для индексации. Читаем через API Foundry, а не из LevelDB, поэтому работает и при запущенном мире;
  - запись итогов сессии в журнал (черновик в отдельной папке «GM Whispers»).
- **Связь с сервером:** WebSocket на `ws://127.0.0.1:<порт>` с локальным токеном. Клиент ГМа работает на той же машине, что и сервер. Ключ API **в Foundry не хранится**.
- **Установка для разработки:** исходник лежит в `GM_Whispers/foundry-module/`, в `Data/modules/gm-whispers` ставим ссылку (junction). Правишь в одном месте, Foundry видит сразу.

### 3.2 Сервер-компаньон

- **Python 3.12**: FastAPI + WebSocket. Почему Python, а не Node: распознавание речи (faster-whisper, GigaAM, Silero VAD), локальные эмбеддинги и рабочий Discord-приём лучше всего живут в Python. Один язык на весь сервер.
- **Модули:** `llm` (Claude), `kb` (индекс и поиск), `context` (сборка промптов), `audio` (бот и распознавание), `session` (расшифровка, итоги), `triggers`.
- Запускается вручную или ярлыком перед игрой. Пишет логи и расшифровку в `GM_Whispers/data/` (не в мир).

### 3.3 Языковая модель: Claude API

| Задача | Модель | Почему | Цена (вход / выход за 1M токенов) |
|---|---|---|---|
| Лор, сложные вопросы, итоги сессии | Claude Opus 5.5 | Качество важнее скорости | $4 / $20 |
| Тактика в бою | Claude Sonnet 5.5 | Баланс скорости и рассуждения | $2 / $10 |
| Фоновый анализ расшифровки, классификация триггеров | Claude Haiku 4.5 | Быстро и дёшево, вызывается часто | $1 / $5 |

- **Кэширование промпта:** библия кампании и системные инструкции кэшируются. Чтение из кэша стоит ~0,05–0,1× цены входа, что сильно удешевляет частые вызовы.
- **Tool use:** для вопросов по лору модель сама вызывает `search_lore`, `get_actor`, `get_scene_notes`, а не получает всё разом.
- **Слой-адаптер:** модель выбирается настройкой, можно переключать по задачам.
- **Доступ:** нужен ключ Claude API с оплатой по токенам. Подписка claude.ai его не заменяет. Ключ ГМ заводит сам в Claude Console и кладёт в `server/.env`. В чат и в мир ключ не попадает.

### 3.4 База знаний (RAG)

- **Нарезка:** по страницам журналов и заголовкам внутри них, фрагменты по ~500–1000 токенов с метаданными: журнал, страница, глава, связанные сцены и NPC.
- **Поиск гибридный:** векторный (локальная многоязычная модель эмбеддингов, кандидат **BGE-M3**, работает на GPU) + полнотекстовый BM25 (нужен для имён собственных, на них векторный поиск ошибается).
- **Хранилище:** SQLite (+ sqlite-vec) или LanceDB. Одна папка, без серверов.
- **Библия кампании:** сжатая сводка из шпаргалок, фракций, партии и текущей главы. Собирается полуавтоматически, правится ГМом.
- **Словарь сущностей** (NPC, места, фракции, предметы) с вариантами написания и падежами.

### 3.5 Discord: главный риск

**Что изменилось.** С 1 марта 2026 Discord пускает в голосовые каналы только клиентов и ботов с поддержкой DAVE (сквозное шифрование голоса). Боту нужно не только подключиться, но и **расшифровать** входящий звук каждого участника.

**Состояние библиотек (на начало октября 2026):**

| Библиотека | Отправка звука под DAVE | Приём звука под DAVE |
|---|---|---|
| `@discordjs/voice` (Node), latest 0.19.2 | Да | В 0.19.0 приём не работал. В 0.19.1 подключение исправили, но были сообщения о потере ~⅓ пакетов при смене ключей. Идёт ветка 1.0.0-dev. **Ненадёжно** |
| `py-cord` 2.8 (Python, май 2026) | Да (заявлено в релизе) | Приём через sinks есть, но поддержку DAVE именно на приём **надо проверить руками**. Есть сообщения, что py-cord корректно работал там, где discord.js падал |
| `discord-ext-voice-recv` (для discord.py) | — | Экспериментальное расширение, статус DAVE неизвестен |

**Решение:** этап 3 начинается с эксперимента на 1–2 вечера. Бот заходит в тестовый голосовой канал, час пишет отдельные дорожки, и мы проверяем потери. Если не работает — запасные варианты:

1. **Craig** (готовый бот для мультитрековой записи). Подходит для итогов *после* сессии: отдельная дорожка на каждого. Для реального времени не годится.
2. **Локальный захват звука** на ПК ГМа: выход Discord + свой микрофон. Работает всегда, но это одна смешанная дорожка, и кто говорит, придётся определять по голосу (диаризация). Это заметно хуже.

**Сеть.** Голос идёт по UDP. Если на ПК ГМа есть файрвол или VPN, проверяем это в том же эксперименте.

**Согласие игроков:** получено 6.10. Остаётся договориться о правилах: что пишется, где хранится, кто видит, когда удаляется (предложение: сырой звук удаляется после итогов, расшифровка хранится только у ГМа).

### 3.6 Распознавание русской речи

| Вариант | Плюсы | Минусы |
|---|---|---|
| **GigaAM-v3** (Сбер, MIT) | Обучен на русском. В независимом бенчмарке лучший на спонтанной речи (WER ~7% против ~7,7% у Whisper turbo) и аудиокнигах. Есть потоковый RNN-T и e2e-версии с пунктуацией. Очень быстрый | Подсказки словарём (hotwords) скромнее, чем у Whisper |
| **Whisper large-v3-turbo** через faster-whisper | Зрелый, есть `initial_prompt` и hotwords для имён, хорошо на чистом звуке | На спонтанной речи хуже GigaAM, бывают «галлюцинации» на тишине |
| Облако (Deepgram, Яндекс SpeechKit и т. п.) | Не грузит ПК | Платно, звук уходит наружу, на русской спонтанной речи не лидер |

**Решение:** не выбирать на глаз. Берём 20–30 минут **вашей** записи, вручную размечаем 5 минут и прогоняем обе модели. Внешний Silero VAD вместо встроенного в Whisper, без «улучшайзеров» звука. Опыт Хабра: агрессивная предобработка ухудшала WER на 6–9 пунктов. Имена чиним словарём сущностей на этапе пост-обработки (нечёткое сопоставление).

Отдельные дорожки от бота решают задачу «кто говорит» без диаризации: Discord-аккаунт → игрок → персонаж.

### 3.7 Готовые решения, которые стоит пощупать

- **foundry-vtt-mcp** (Adam Dooley): MCP-мост между Foundry и Claude Desktop. Заявлена поддержка **v13 и v14**, 43 инструмента (персонажи, компендиумы, журналы, токены, NPC), есть режим «только чтение». Работает **по подписке claude.ai, без API-ключа**. Это не наш продукт (нет боевой панели, нет аудио), но за один вечер в DOD_TEST покажет, какие вопросы к ИИ реально полезны ГМу. Отличный этап 0.

## 4. Архитектура

```
                    ПК ГМа (Windows)
┌──────────────────────────────────────────────────────────┐
│  Foundry VTT 14 (сервер :30000)                          │
│   └─ клиент ГМа ── модуль gm-whispers (панель, контекст) │
│                         │ ws://127.0.0.1 + токен         │
│  GM Whispers Core (Python) ◄────────┘                     │
│   ├─ kb: индекс журналов (SQLite/LanceDB + BGE-M3 на GPU) │
│   ├─ context: сцена/бой/партия → промпт                   │
│   ├─ llm: Claude API (Opus / Sonnet / Haiku) ─────────────┼──► api.anthropic.com
│   ├─ audio: Discord-бот (DAVE) → VAD → GigaAM/Whisper ◄───┼──► Discord voice (UDP)
│   ├─ triggers: словарь сущностей, сигналы темпа           │
│   └─ session: расшифровка, итоги → журнал Foundry         │
│  GM_Whispers/data/: индекс, расшифровки, логи             │
└──────────────────────────────────────────────────────────┘
Игроки: подключаются к Foundry и Discord как обычно, помощника не видят.
```

**Безопасность:**

- ключ API лежит только в `.env` сервера;
- сервер слушает только `127.0.0.1`;
- модуль ничего не пишет в настройки мира с `scope: world`, кроме безобидных флагов;
- итоги сессии создаются в журнале с правами «только ГМ».

## 5. Подсказки в реальном времени: как не превратиться в шум

| Тип | Пример | Нужна ли модель | Задержка |
|---|---|---|---|
| По кнопке | «Что я упускаю?» → разбор последних 10 мин + состояние игры | Да (Sonnet/Opus) | 5–20 с, ок |
| Триггер-сущность | Назвали NPC/место → карточка из базы | **Нет**, словарь + нечёткое сопоставление | < 1 с после распознавания |
| Триггер-вопрос | Игрок спросил про лор → факт из книги | Haiku для классификации + поиск | 2–5 с |
| Напоминание | Зацепились за деталь трёх сессий назад → что было сказано | Поиск по прошлым итогам | 2–5 с |
| Тихий сигнал | 15 мин спора без продвижения; игрок молчит час | Haiku раз в 2–3 мин или простая статистика | не важна |

Настройки шумности: лимит подсказок в час, типы вкл/выкл, «тихий режим» на боёвку.

## 7. Риски

| Риск | Вероятность | Влияние | Что делаем |
|---|---|---|---|
| Приём голоса под DAVE не работает или теряет пакеты | Высокая | Нет F4 в реальном времени | Эксперимент до разработки; запасные варианты: Craig (после сессии), локальный захват |
| Перерасход по API | Низкая | Лишние траты | Месячный лимит в Claude Console, счётчик токенов в логах сервера |
| Сеть до Discord (UDP) с ПК ГМа | Низкая | Бот не слышит | Проверить в эксперименте |
| Распознавание путает имена и перекрикивания | Средняя | Ложные/пропущенные триггеры | Словарь сущностей, отдельные дорожки, бенчмарк на ваших голосах |
| Модель выдумывает лор | Средняя | Неверные подсказки | Обязательные ссылки на источник, «не нашёл» вместо догадок |
| Подсказки отвлекают | Средняя | ГМ выключит помощника | Лимиты, приоритет кнопки над авто |
| Нагрузка на GPU (Foundry + ASR + эмбеддинги) | Низкая | Тормоза | Эмбеддинги считаем заранее; ASR в int8 |
| Утечка спойлеров игрокам | Низкая | Высокое | Только GM-рендер, никакого чата/сокетов, тест под учёткой игрока |
| Обновление Foundry/dnd5e ломает модуль | Средняя | Ремонт | Минимум патчей ядра, только публичное API и хуки |

## 10. Решения и открытые вопросы

**Решено 6.10:**

- Тестовый мир переименован в `dod-test`.
- Ключа API пока нет, способ оплаты есть: ГМ заводит ключ сам.
- ГМ — админ Discord-сервера, бота можно добавить.
- Игроки согласны на запись голоса.
- Приоритет источников при расхождениях: шпаргалки ГМа > книга приключения > справочник мира.
- Клиент ГМа работает на том же ПК, где сервер Foundry.
- Организация Claude API оказалась отключена: ГМ запрашивает проверку в поддержке Anthropic. Пока советник работает на OpenAI (gpt-6.1-sol для лора и тактики, gpt-6-luna для фона). Сервер выбирает провайдера по названию модели в `.env`, возврат на Claude — замена трёх строк.
