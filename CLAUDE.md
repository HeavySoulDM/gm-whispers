# GM Whispers — инструкция для Claude (любой чат)

Проект Di: ИИ-помощник мастера для Foundry VTT (кампания Dungeons of Drakkenheim, dnd5e, русский язык).
Разработка идёт в разных чатах. Этот файл — вход. Читать в начале любой задачи, остальное — по ссылкам.

## С чего начать задачу

1. Прочитать `docs/ROADMAP.md` (где мы, что дальше) и, если задача касается кода, `docs/ARCHITECTURE.md` (что где лежит, API, потоки).
2. Проверить, что папка `H:\Cowork\GM_Whispers` подключена к чату (`device_bash`: `ls $HOME/mnt/GM_Whispers`). Если нет — попросить Di добавить папку. Файлы на ПК Di — источник истины; копия в контейнере может отстать.
3. Перед правкой файла забрать его актуальную версию с ПК (`device_stage_files`), не переписывать по памяти.
4. Сказать Di в одну строку, что будет сделано, и приступать. Вопросы — только если ответ меняет объём работы.

## Правила работы

- **Общение по-русски**, коротко, без лишней терминологии: Di — не программист, объяснять «что это даёт», а не «как устроено».
- **Секреты не читать и не печатать**: `server\.env` содержит ключи API и токены. Менять в нём только нужные строки скриптом, не перезаписывать файл целиком.
- **Боевой мир `dod` — осторожно**: модуль там включён с 7.10. Опасные эксперименты — в `dod-test`. Перед изменениями, которые пишут в мир (новые типы документов, миграции), просить сделать бэкап.
- **Пути на ПК**: проект `H:\Cowork\GM_Whispers`, Foundry `H:\Foundry_14`, записи Craig `D:\Google Drive\Craig`. Модуль подключён к Foundry ссылкой, копировать не нужно.
- **Файлы Windows**: `.bat`, `.vbs` — в CRLF; остальное — LF. Python venv на ПК (`server\.venv`) из контейнера не запускается — сервер проверять в контейнере на копии кода.
- **Версии**: при заметных изменениях поднять `module.json: version` и `server/gmw/__init__.py: __version__` одинаково, добавить запись в `scripts/changelog.js` сверху.
- **Не финальный продукт**: обратная совместимость настроек (`.env`, json) важнее красоты; новые поля — с умолчаниями.
- **Автозапуск, автообновление, любые действия «за пользователя»** — только по явному решению Di, по умолчанию выключено.

## Как проверять перед отправкой

- Python: `python -c "import ast,glob;[ast.parse(open(f).read()) for f in glob.glob('server/gmw/*.py')]"` + прогон через `fastapi.testclient` с временным `.env` и `data/test/export.json` (есть в `H:\Cowork\GM_Whispers\data\test`).
- JS: `node --check` на все `scripts/*.js`; для окон — макет на jsdom (`ApplicationV2`, `game.settings`, `fetch`), образец в чате 8–9.10 (`run.mjs`).
- Отправка на ПК: `device_commit_files` только изменённых файлов. После отправки сказать Di, что перезапустить: `start.bat` (сервер) и/или F5 (модуль).
- Что не проверено вживую — так и писать, и отмечать 🧪 в ROADMAP.

## Как заканчивать задачу

1. Обновить `docs/ROADMAP.md`: статус этапа, новые 🧪, решения Di.
2. Если изменилась структура/API — поправить `docs/ARCHITECTURE.md`; если изменился порядок действий пользователя — `README.md`.
3. Обновить сводку в проекте Claude `Foundry_14` → `claude/gm-whispers.md` (кратко: статус, что проверить, что дальше).
4. В ответе Di: что изменилось для него, что проверить, следующий шаг. Без пересказа шагов.
